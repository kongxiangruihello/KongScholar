# KongScholar 2.9.0

2026-10-25 · 第26次构建 · macOS13+ · Apple芯片 / Intel通用版

本版落实上一轮30项建议的第19—30项，完善写作、交稿、教学与研究回望。此前第1—18项的本机功能继续保留；GitHub远端同步与Apple公证仍受连接、登录和证书条件限制，尚未完成，不能视为30项全部对外发布完成。

## 十二项功能与入口

19. **研究问题与章节对应矩阵**：所有工具 → 问题与章节对应矩阵。记录某章计划承接、正文已回应或仍待补充的问题，填写回应方式及正文段落。标为正文已回应时要求当前正文中有唯一段落；段落后来改变或重复时提示复核。已有章节的研究问题关联继续显示为“既有关联，回应待核”。矩阵每组最多20个问题、12章/节，可分别翻组，当前格子的承接说明列在下方。
20. **关键证据依赖检查**：所有工具 → 关键证据依赖与反证。可在论点中从支持史料及推理依据手工指定关键证据；未指定时暂按全部已关联支持和推理材料检查。根据同一文献编号和已明确记录的原刊/转载/译文/节录/转引链分组，提示没有支持材料、单条史料或同一来源组依赖，显示缺失及已移出支持范围的旧关键证据。多组材料也不等于独立证据，数量不判定论点成立。
21. **反证处理追踪**：在同一页面逐条为论点已列反证建立处理记录，关联章节与正文段落，记录待处理、已解释、待补材料、需调整判断或已调整判断以及理由。完成解释/调整须有当前正文中可唯一定位的段落。论点、来源或段落变化后，原处理记录保留并提示复核；取消论点中的反证关联也不删除历史处理。
22. **论证衔接与跳步提示**：所有工具 → 论证衔接与跳步提示。依据已有事实、解释、假设、支持材料、范围限定、反证说明及段落作用标记，提示尚未明确写出的衔接。可将缺项转成论点查证任务，同来源不重复创建。检查不进行自动语义判断，未发现缺项也不能证明推理充分。
23. **章节结构调整预览**：在原“书稿与论文目录”上移、下移、更改上级或移除失效目录项时，先进入预览，显示目录编号变化及相关内部引用、任务、同行意见。填写理由并确认后才保存；预览后相关结构或关联变化会拒绝执行。正文及关联继续使用稳定章节编号，既有冻结稿与交付稿保留。仅修改写作状态仍直接保存。调整历史最多100次，不自动丢弃；写入失败时保留当前预览。
24. **修订前后并排写作**：所有工具 → 修订前后并排写作，或章节写作台上方入口。建立轮次时，选择该章已有旧版本，或将建立轮次时的当前稿固定为参照，填写修订目标。左侧旧稿及其脚注为独立快照，右侧修改当前章节正文，沿用原有自动保存与失败阻止离开机制，保留当前脚注。参照版本或章节不能在已有轮次中更换，需另建轮次；原版本之后变化不回写固定参照。
25. **交稿文件与反馈对应**：所有工具 → 交稿文件与反馈对应。通过APP导出的新Word，以及包含Word的阶段成果包，在正文标题后带KS29稿次标识，另存实际导出的正文/脚注快照；旧导出历史钩子不会重复创建同一条记录。取消导出不记成功。若文件已保存但本机历史写入失败，会明确提示，可在本次会话中重试保存稿次快照；退出前仍须保存，外部导出文件请另行保留。返回稿读取传统Word批注时，用标识查找候选，并展示正文锚点；必须人工确认稿次或明确保留为稿次未定，所选批注才接入意见收件簿。标识可被复制或在修改中丢失，只提供匹配线索，不是文件身份认证。旧Word仍可手工确认，现代线程批注及修订痕迹仍不在导入范围内。
26. **交稿材料完整性清单**：所有工具 → 交稿材料完整性清单。按当前项目检查作者信息、摘要、关键词、参考文献、图表、附录和目录/正文，记录待准备、已核或不适用及依据；已核须先有相应材料。各项保留当时核验依据，相关资料变化时提示复核；显示最新核验，不覆盖旧记录。清单证明准备状态，不能代替对最终导出文件的人工检查；作者字段准备好也仍须按排版预设决定是否输出扉页。
27. **图表与史料影像目录**：所有工具 → 图表与史料影像目录。保存项目、图/表/影像类别、编号、标题、出处史料、证据影像、采用版本、拟放章节/段落与图注来源说明。同一项目同类编号不能重复，可返回证据影像与史料，导出本项目图表清单。此项生成清单，不自动将图像嵌入Word；原图、图注和最终编号仍由您核对。
28. **课程材料更新提醒**：所有工具 → 课程材料更新提醒。为研读课、讲义和每周课程建立人工核对基线；比较当前已关联史料的原文、整理层、解释、页码、出处和文献字段。每周课程同时检查其关联研读课的材料。变化后提示复核并要求本次说明，旧基线保留，预览期间材料再变化会拒绝确认。没有基线时明确标记，不倒推旧材料是否已核。基于本机已建立的关联，不自动监控外部PDF或未关联讲义，不创建外部提醒或自动发送消息。复核历史最多2000条。
29. **下次指导会谈准备单**：所有工具 → 下次指导会谈准备单。按论文从最近日期的会谈公开意见、稿次意见和最近两稿对照中未解决的逐项回应生成可编辑提纲，另填学生实际回应、拟会谈日期和拟确认行动，保存当时依据。私人会谈笔记不进入生成快照或导出提纲，已解决项不列入继续讨论。生成后原指导资料变化时，新建提交会要求重新生成；已保存准备单可继续编辑正文，既有摘要与原指导记录不互相回写。
30. **个人研究周记与月度回望**：所有工具 → 研究周记与月度回望。选择项目、周记/月度回望和起止日期，汇集已记录的问题演变、材料整理活动、正文/论证修订和当前存疑判断，另由您补充重要发现、研究反思、未解问题与后续计划。月度默认从本月第一天至今日，可自行改范围。保存摘要为当时快照，后续活动不改写旧周记。活动日志最多10000条，各类摘要最多列出前200条，不倒推未记录的完成日期，不按活动数量评价研究质量。可导出周记或月度回望。

## 保存与升级保护

- 新增问题承接、反证、修订、图表、核验和会谈准备长表单支持原有独立草稿及历史恢复。正式提交前仍是本机草稿，未写入磁盘的最后约一秒输入可能无法恢复。第一次保存草稿也先完成本版本升级保护。
- 2.9首次写入前核验专用升级备份；最低读取版本29，拆分存储版本6。固定参照稿、教学基线和会谈生成依据进入受校验归档，完整JSON和工作备份能完整组装读回。2.8及更早版不能继续写入此资料目录，回退须使用升级前完整备份，并另行保留2.9新增记录和草稿。
- 完整研究库/工作备份仍上限256MB，外部PDF、KongFolio工程、稿件和图像原件仍须独立备份。本次不修改外部原件或其他APP，不触及正式研究库。
- 研究资料、学生资料、独立草稿、附件及备份只在本机。GitHub仍仅允许APP源码、合成测试与版本说明，保留原有资料排除规则。
